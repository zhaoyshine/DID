# DID

一个 Claude Code 插件，把规划和执行分开。onset 规划：五位专家组成的专家组把你访谈一遍，把需求问清楚，一次只写一个 phase 的 High-Level 计划。dreamwalking 执行：照这份计划逐 task 跑完，把实际结果回填进计划文档。结果回到专家组手里，验证方向，再规划下一个 phase，直到需求达成。

适合多步骤、需要和你对齐方向的事。简单的一次性任务不用它。

## 快速开始

在 Claude Code 中安装：

```
/plugin marketplace add zhaoyshine/DID
/plugin install did
```

需要 Claude Code v2.1.196 及以上：计划文档和草稿的路径模板都用了 `${CLAUDE_PROJECT_DIR}`，该占位符自这个版本起才展开，旧版本解析不了路径。

## 用法

```
/did:onset 帮我检查这个项目，再发布到 GitHub
```

专家组先访谈你——检查什么、什么算通过——然后写出第一个 phase 的计划，存到项目的 `.claude/DID/` 下，派 dreamwalking 去执行。执行完，专家组读回填的实际结果，验证方向，判断要不要下一个 phase。计划文档全程可读可改，你随时能打断，补信息或改方向。

## 为什么这么设计

同一个 agent 既做决策又做执行时，计划会悄悄过期：决策时看到的世界，执行时已经变了。DID 把两者切开，专家组的注意力全在访谈用户、收集信息、预判副作用上，dreamwalking 严格照计划跑，卡住的 task 只把事实写进结果，不即兴打补丁。

需求早期信息不足，一次性铺开所有 phase，后面的就建立在猜测上，执行结果一偏离就得推倒重写。所以每轮只写当前信息能支撑的部分，下一个 phase 等真实反馈回来再规划。

两个角色之间只有计划文档这一个接口：哪边出了问题，翻文档就能看出来。
