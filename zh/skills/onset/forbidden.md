# 用户禁止事项

## 开发工作流

- 注释只是复述实现，对读代码的人没有任何帮助（重复代码已经表达的「是什么」）
- 冗长啰嗦的注释或超过 3 行（注释能省则省；要写就只写要点）
- 随手重构无关代码，或夹带超出范围的功能
- 整个开发流程全用英文（代码、注释、变量名、提交信息、Jira task、PR 标题与正文）

## 提交与 PR

- 试图绕过 pre-commit hook
- 使用 git add -A，或用 git add 一次性加入全部文件；应列出具体文件

## Git 与 Worktree

- 在原始仓库工作目录中 commit / checkout / 修改文件 / 切分支 / pull（所有改动必须隔离在 git worktree 里）
- 使用 git worktree remove / rm -rf 删除 worktree 目录（做完保持原样，交给下游）
- 使用 git push --force / --force-with-lease（仅追加提交、不改写历史时除外）
- 使用 git reset --hard、强制推送
- 在仓库目录之外使用 git 命令
- 把主分支名硬编码为 main/master
- 工作区不干净时擅自 stash / reset / clean / checkout
- 使用非快进合并（git pull 必须加 --ff-only）

## 测试

- 写永远无法触发的测试（错误路径没有可靠的注入机制就不要写；不要给防御性代码加仅作文档用途的测试）
- 跑全量测试套件（只跑与改动相关的测试 / Lint / Check）

## 调研

- 下结论不给依据
- 明明答案在代码里却不查
- 用空洞的套话当结论、洞见（例如「这很重要」「值得学习」「AI 是趋势」）
- 没有发现、结果时编造或凑数（应如实说「未发现问题」「只有 N 条」）
